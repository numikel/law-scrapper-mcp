# Changelog - v4.4.0

All notable changes to the `law-scrapper-mcp` project for version v4.4.0 will be documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

## [4.4.0] - 2026-09-12

Every tool now tells the host how it behaves. `tools/list` carries a Polish display title and all
four MCP behaviour hints for each of the 13 tools, so a client with an approval gate no longer has
to assume the protocol's pessimistic defaults (`readOnlyHint=false`, `destructiveHint=true`). The
structured output contract that v3.0.0 fixed is now pinned by its own test, and the one field that
never carried data is gone from it.

### BREAKING — `metadata` removed from every tool result

`EnrichedResponse.metadata` is removed. The field was advertised in the `outputSchema` of all 13
tools but was never filled: every response carried `"metadata": {}`. Results now contain only
`data` and `hints`, and the field is gone from every `outputSchema`. A client that read
`result["metadata"]` gets a missing key instead of an empty object. No information is lost.

This ships as a MINOR release with an explicit note, following the precedent of v3.1.1 and v4.3.0.

### Added

- Tool annotations on all 13 tools: `readOnlyHint=true`, `destructiveHint=false` and
  `idempotentHint=true` everywhere; `openWorldHint=true` on the seven tools that call
  `api.sejm.gov.pl` (`search_legal_acts`, `browse_acts`, `get_act_details`, `compare_acts`,
  `analyze_act_relationships`, `track_legal_changes`, `get_system_metadata`) and `false` on the six
  that work only on in-memory data. Annotations are hints, not enforcement.
- A Polish `title` on every tool, shown by hosts instead of the snake_case name.
- A README table listing each tool's title, `readOnlyHint` and `openWorldHint`.

### Changed

- The in-memory state a tool creates (result sets, loaded documents, cache entries) is treated as
  process-local cache, not as the tool's environment. The reasoning, and the condition under which
  it stops holding (a durable store), is recorded in `tools/annotations.py`.

### Internal

- New contract test: for every tool, `structuredContent` validates against `outputSchema`
  (jsonschema, Draft 2020-12), and the text block stays the full JSON copy recommended by the
  MCP specification for backwards compatibility.
- An architecture test rejects any tool decorator without a `title=` and an annotation preset.
- `jsonschema` is now an explicit development dependency.

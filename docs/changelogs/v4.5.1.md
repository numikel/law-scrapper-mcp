# Changelog - v4.5.1

All notable changes to the `law-scrapper-mcp` project for version v4.5.1 will be documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

## [4.5.1] - 2026-11-13

Dependency maintenance: the three open Dependabot updates (#73, #104, #107) in one change, plus the
`opentelemetry-api` fix that `pip-audit` reports and no Dependabot pull request carried. One of the
four advisories could be used against this server and is described under Security. A client sees one
difference, in the handshake of the older protocol era (see Changed); `tools/list`, tool results and
tool error texts are unchanged.

### Install

The release attaches the core and every source module as wheels, all version 4.5.1; a module requires
the core of exactly its own version.

```bash
RELEASE=https://github.com/numikel/law-scrapper-mcp/releases/download/v4.5.1
pip install "$RELEASE/law_scrapper_mcp-4.5.1-py3-none-any.whl" \
            "$RELEASE/law_scrapper_mcp_voivodeship_journals-4.5.1-py3-none-any.whl"
```

Add `law_scrapper_mcp_saos-4.5.1-py3-none-any.whl` for court judgments. In the container image every
module is installed and off; enable one with `LAW_MCP_SOURCE_MODULES=-*,<name>`.

### Security

- Locked `opentelemetry-api` moves from 1.45.1 to 1.45.2, which fixes quadratic-time parsing of a
  `traceparent` value (GHSA-mf5v-w3w3-f6cg, CVE-2026-126360). This one was reachable. The MCP SDK
  reads trace context from `params._meta` of every request, and a JSON string, unlike an HTTP
  header, may hold the newline the attack needs. Reproduced against `POST /mcp` on v4.5.0: one
  request with a 48 kB `traceparent` held the event loop for 8 seconds, during which no other client
  was served; the time grows with the square of the length. On 1.45.2 the same request is answered in
  0.02 seconds and the malformed value is ignored. With `LAW_MCP_AUTH_MODE=bearer` or `oauth` only an
  authenticated caller could send it; a loopback server with `none` accepted it from any local
  process. The `[tool.uv]` override floor moves to 1.45.2, and a transport test now sends that request
  and bounds the time the answer may take.
- The core package now declares `opentelemetry-api>=1.45.2` itself. A `[tool.uv]` override reaches
  only a uv resolution of this repository (`uv sync`, the container image); a wheel carries the
  package's own dependency list, and `pip install` of a newer wheel keeps every installed dependency
  that still satisfies it. Checked on an environment holding `opentelemetry-api` 1.45.1: without the
  declaration, installing the 4.5.1 wheels over it left 1.45.1 in place; with it, the install moves
  to 1.45.2. The CI `packages` job cannot see this, because it installs the wheels from the
  repository directory, where the overrides apply.
- Locked `soupsieve` (transitive, through `markdownify` and `beautifulsoup4`) moves from 2.10 to 4.1.
  This closes GHSA-mmhr-3c5m-f64f (CVE-2026-126190, polynomial time on nested documents, fixed in
  4.0), GHSA-7g44-g9rc-x53w (CVE-2026-126193, unbounded recursion in the selector parser) and
  GHSA-6655-6qjp-jx7x (CVE-2026-126191, exponential backtracking on escapes), both fixed in 3.0.2.
  None was reachable: all three need a CSS selector to be compiled or matched, and the HTML to
  Markdown converter walks the tree without one. A test now refuses every `soupsieve` entry point
  during a conversion, so this stays true. For the same reason the breaking changes of 4.0 (selectors
  no longer descend into `template`, and treat `iframe` content as ordinary children) change nothing:
  the Markdown of the act and journal page fixtures is byte-identical before and after.
  `beautifulsoup4` asks only for `>=1.6.1`, so the floor is a new `[tool.uv]` override at 4.0, the
  first release clear of all three; 4.0.1 and 4.1 add further quadratic-time fixes. This floor stays
  an override, because the advisories are not reachable: an environment that was installed from
  wheels keeps its `soupsieve` until `pip install --upgrade soupsieve`, which is what clears the
  finding of an audit tool there.

`pip-audit` reports nothing against the new lock.

### Changed

- MCP Python SDK `mcp[cli]` moves from 2.2.0 to 2.3.0, and `mcp-types` with it. The server's answers
  were captured before and after over STDIO and HTTP, in both protocol eras (handshake, tool listing,
  a successful call, failing calls, unknown tool and method), and differ in one place:
  - **Handshake of a 2025-11-25 client.** The `capabilities` object in the `initialize` result no
    longer contains an empty `"experimental": {}`. The SDK now leaves the key out when nothing is
    configured. `prompts`, `resources` and `tools` are as before. A client that reads
    `capabilities.experimental` should accept its absence. Clients of the 2026-07-28 era
    (`server/discover`) never received the key.

  The other behaviour changes of 2.3.0 do not show here. It requires `httpx2>=2.10.0`, which the
  existing floor of 2.12.0 already meets. It refuses a tool with an invalid `x-mcp-header` annotation
  at registration; no tool of the core or of a module declares one. It no longer runs a `tools/list`
  for every `tools/call` to validate `Mcp-Param-*` headers, which has no visible effect on this
  server. The pinned MCP conformance suite gives the result `conformance-baseline.yml` records,
  core-only and with a module active: 27 checks pass and the 13 scenarios of the baseline fail as
  expected.
- The CI and release workflows use `astral-sh/setup-uv` v10.3.3 and
  `softprops/action-gh-release` v3.0.4, still pinned by commit SHA.
- New policy tests keep a dependency bump whole: the locked SDK must equal the pin in
  `pyproject.toml`, `README.md` and `CLAUDE.md` must name the pinned SDK version, each security
  floor must be a `[tool.uv]` override that the lock honours, and a floor whose advisory is reachable
  must also be a dependency of the package. The handshake of the older protocol era, which had no
  test, is now pinned with its whole `capabilities` object.

# Changelog - v4.5.2

All notable changes to the `law-scrapper-mcp` project for version v4.5.2 will be documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

## [4.5.2] - 2026-11-14

Maintenance release. Nothing under `src/` changes: the server, its 13 tools and the two source
modules behave exactly as in 4.5.1, and the dependency lock is the same. The packages differ from
4.5.1 only in their version number. An installation on 4.5.1 gains nothing by upgrading; the changes
are for people who develop the project.

### Install

The release attaches the core and every source module as wheels, all version 4.5.2; a module requires
the core of exactly its own version.

```bash
RELEASE=https://github.com/numikel/law-scrapper-mcp/releases/download/v4.5.2
pip install "$RELEASE/law_scrapper_mcp-4.5.2-py3-none-any.whl" \
            "$RELEASE/law_scrapper_mcp_voivodeship_journals-4.5.2-py3-none-any.whl"
```

Add `law_scrapper_mcp_saos-4.5.2-py3-none-any.whl` for court judgments. In the container image every
module is installed and off; enable one with `LAW_MCP_SOURCE_MODULES=-*,<name>`.

### Changed

- Dependabot updates the Python dependencies through the `uv` ecosystem instead of `pip`. The `pip`
  ecosystem edits `pyproject.toml` and never `uv.lock`, so its version updates could not pass
  `uv lock --locked` and were replaced by hand in 4.4.1 and 4.5.1. `versioning-strategy` is
  `increase-if-necessary`: a requirement that already allows the new release keeps its floor and only
  the lock moves, while the exact `mcp[cli]` pin is rewritten.

### Fixed

- The offline guard of the module tests could be bypassed by a proxy. The guard refuses a name lookup
  for a non-local host, so that a test which forgot its mock fails instead of sending traffic to SAOS
  or a voivodeship journal. A request handed to a proxy never makes that lookup, because the proxy
  resolves the name: with `HTTPS_PROXY` set, an unmocked request left the test process. Both guards
  now also set `NO_PROXY=*`, and each module has a control with a proxy served by the test itself,
  which must receive nothing. This affects the test suites only.

# Changelog - v4.4.1

All notable changes to the `law-scrapper-mcp` project for version v4.4.1 will be documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

## [4.4.1] - 2026-09-25

Dependency maintenance: every open Dependabot update (#58, #69, #70) plus the `anyio` fix that
`pip-audit` reports. Nothing a client sees changes: the `tools/list` payload of all 13 tools and
the text of every tool error are byte-identical to v4.4.0. The three behaviour changes the new MCP
SDK would have brought in are held back (see Changed).

### Security

- Locked `anyio` (transitive, through httpx/httpcore, `mcp` and Starlette) moves from 4.11.0 to
  4.14.2. This closes CVE-2026-63374 (GHSA-82r6-8w77-94w6, TLS to internationalized domain names)
  and CVE-2026-64847 (GHSA-5p39-cfhj-2xmp, an undrained stderr pipe on process-pool workers).
  `sniffio` leaves the lock with it.
- Locked `soupsieve` (transitive, through markdownify and beautifulsoup4) moves from 2.8.4 to
  2.10. This closes two ReDoS advisories, GHSA-j934-xhv5-fg8f and GHSA-gjv8-xp57-g29c
  (CVE-2026-85999, CVE-2026-86000). Neither was reachable, because this server never evaluates a
  CSS selector; the bump clears the audit finding.

### Changed

- MCP Python SDK `mcp[cli]` moves from 2.0.0 to 2.2.0, and `mcp-types` with it. Three SDK
  changes are held back so that clients and operators see what v4.4.0 gave them:
  - **Tool error text.** From 2.1 the SDK passes a tool exception's text to the client only for
    an anticipated `ToolError`; any other exception reaches the client as a bare
    `Error executing tool <name>`. `ToolExecutionError` now subclasses `ToolError`, so the Polish
    message still arrives unchanged.
  - **Logs.** 2.2 logs every failed tool call at INFO with the full message, and that message
    quotes the caller's input. Its `mcp.server.mcpserver.server` logger is now held at WARNING,
    as `httpx` and `httpcore` already are, so no caller input reaches stderr at the default
    level. SDK crash records (ERROR) still appear.
  - **OAuth startup.** `AuthSettings.validate_token_resource` is now set explicitly to `false`,
    which is how 2.x already behaved when it was unset. This silences the deprecation warning
    that 2.2 prints on every start with `LAW_MCP_AUTH_MODE=oauth`. The JWT verifier still checks
    the token's `aud`.

  The SDK's new limits on stateful sessions (`session_idle_timeout`, `max_sessions`) do not apply
  here, because the HTTP transport stays stateless.
- The CI and release workflows use `astral-sh/setup-uv` v10.2.0, still pinned by commit SHA.

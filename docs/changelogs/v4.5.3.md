# Changelog - v4.5.3

All notable changes to the `law-scrapper-mcp` project for version v4.5.3 will be documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

## [4.5.3] - 2026-11-23

Dependency maintenance: the three open Dependabot updates (#110, #111, #112) in one change. Nothing
under `src/` changes. A client sees no difference: `tools/list` (every input and output schema, for the
core alone and with all source modules on) and a sample tool result are byte-identical before and
after the update.

### Install

The release attaches the core and every source module as wheels, all version 4.5.3; a module requires
the core of exactly its own version.

```bash
RELEASE=https://github.com/numikel/law-scrapper-mcp/releases/download/v4.5.3
pip install "$RELEASE/law_scrapper_mcp-4.5.3-py3-none-any.whl" \
            "$RELEASE/law_scrapper_mcp_voivodeship_journals-4.5.3-py3-none-any.whl"
```

Add `law_scrapper_mcp_saos-4.5.3-py3-none-any.whl` for court judgments. In the container image every
module is installed and off; enable one with `LAW_MCP_SOURCE_MODULES=-*,<name>`.

### Changed

- The lock moves the runtime dependencies to the releases Dependabot proposed. `pyproject.toml` is
  unchanged: every floor already admits them, so an installation from wheels keeps whatever release
  it has until it upgrades, and both the old and the new releases pass the suite.
  - `python-dateutil` 2.9.0.post0 → 4.0.0 (#111). The release drops `six` and adds `tzdata`. The
    server uses only `relativedelta`, for `calculate_legal_date`; the 3.0 and 4.0 changes to it
    (`yearday=366`, `__ne__` against `None`) touch nothing it calls. New tests pin deadlines at month
    ends, leap days and year boundaries, and the order in which years, months and days are combined.
  - `uvicorn` 0.37.0 → 0.54.0. HTTP/2 and `zuvloop` stay opt-in and unused. 0.53 added `::1` to the
    default `FORWARDED_ALLOW_IPS`; this server passes `proxy_headers=False` and an empty
    `forwarded_allow_ips`, so the change does not apply. A new test drives the real HTTP process with
    the limiter on and rotates a forged `X-Forwarded-For`: the third request is still answered with
    429.
  - `markdownify` 1.2.2 → 1.2.3, which reworks the conversion of `<br>`. The Markdown of act lines,
    SAOS judgment text, headings and table cells is the same as before, and new tests pin it exactly.
  - `pydantic` 2.12.2 → 2.14.3 (`pydantic-core` 2.50.4), `pydantic-settings` 2.11.0 → 2.16.2,
    `httpx2`/`httpcore2` 2.12.0 → 2.16.0 (a runtime dependency of the MCP SDK),
    `typing-extensions` 4.16.0, `typing-inspection` 0.4.5.
- Development tools (#110, #112): `mypy` 1.19.1 → 2.4.1, `ruff` 0.15.1 → 0.17.4, `pytest` 9.1.1 →
  9.2.0, `pytest-asyncio` 1.3.0 → 1.4.1.post1, `pytest-cov` 7.1.0, `respx` 0.23.1, `jsonschema`
  4.26.0. mypy 2.4.1 reports no issues. ruff 0.17 also formats Python code blocks inside Markdown
  files, which failed the lint job of #110; the one snippet in `tests/TEST_SUITE_SUMMARY.md` is
  reformatted. pytest 9.2 warns that the `anyio` pytest plugin imports the `CallSpec2` alias, which
  pytest 10 removes; the warning comes from `anyio`, not from this project.

`pip-audit` reports nothing against the new lock.

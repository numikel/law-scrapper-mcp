# Changelog - v4.5.0

All notable changes to the `law-scrapper-mcp` project for version v4.5.0 will be documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

## [4.5.0] - 2026-11-08

Installable source modules. The server can now serve more legal sources than Dziennik Ustaw and
Monitor Polski, each as a separately installed package that an operator switches on by name: the
voivodeship official journals and Polish court judgments from SAOS. This is the first release that
publishes the modules next to the core. Without a module installed, or with
`LAW_MCP_SOURCE_MODULES=-*`, the 13 core tools, their parameters, `outputSchema` and error texts behave
as in 4.4.2; nothing here needs a migration.

### Install

The release attaches the core and every source module as wheels, all version 4.5.0; a module requires
the core of exactly its own version.

```bash
RELEASE=https://github.com/numikel/law-scrapper-mcp/releases/download/v4.5.0
pip install "$RELEASE/law_scrapper_mcp-4.5.0-py3-none-any.whl" \
            "$RELEASE/law_scrapper_mcp_voivodeship_journals-4.5.0-py3-none-any.whl"
```

Add `law_scrapper_mcp_saos-4.5.0-py3-none-any.whl` for court judgments. In the container image every
module is installed and off; enable one with `LAW_MCP_SOURCE_MODULES=-*,<name>`.

### Added

- **Source modules.** The core discovers installed packages in the entry-point group
  `law_scrapper_mcp.source_modules` and activates them at startup. `LAW_MCP_SOURCE_MODULES` is read
  left to right and the last token about a module wins: `name` enables, `-name` disables, `*` and `-*`
  enable or disable every installed module, so `-*,saos` runs SAOS alone. A disabled module is never
  imported. A name clash with a core tool, an unknown name that is still enabled, or a failing module
  start stops the server with a Polish message that names the module and the token that switches it
  off. The conventions for writing a module are in `docs/source-modules.md`.
- **Voivodeship official journals** (module `voivodeship-journals`, publisher codes `POL_WOJ_*`). The
  existing tools search, browse, load, read and track acts from 12 of the 16 journals; the other four
  are listed as unavailable with the reason (no answer, or an incomplete TLS chain) and are never
  contacted. `get_system_metadata(category="publishers")` lists DU, MP and the 16 journals, and the
  `publisher` parameter accepts a voivodeship name as well as a code. Filters a journal does not support
  (`in_force`, `date_from`/`date_to`, more than one keyword) fail before any request; a scanned PDF
  reports that it has no text and gives the PDF link.
- **Court judgments from SAOS** (module `saos`). `search_saos_judgments` searches by phrase,
  signature, date range, court type and judgment type, stores the result for `filter_results`, can add
  court-portal links for the first five results, and has a bounded `labour_only` scan for labour cases.
  `get_saos_judgment_details` returns one judgment; with `load_content=true` it loads the text and,
  for a common-court sentence, its reasoning, so `read_act_content`, `search_in_act` and
  `list_loaded_documents` work on it as on an act. When SAOS holds no reasoning, the text ends with a
  server note that says so. Judge and reporter names are never parsed.
- **Source coverage.** `get_system_metadata(category="coverage")` (also part of `all`) reports how far
  each active source reaches: newest document, count, years, the date of the measurement and whether
  the value is measured or a recorded fallback. Search and browse add a hint only when a query reaches
  past a source: a year it does not have, or a window more than 30 days after its newest document.
  Coverage is measured lazily, at most once per 24 hours per source and process, and never at startup.
- **Operator contact.** `LAW_MCP_CONTACT` (an `http(s)://` URL or an e-mail address) replaces the project
  URL in the `User-Agent` sent to every upstream host. Unset, the header is byte-for-byte as before.
  An HTTP deployment beyond loopback that keeps the default contact logs one startup warning.
- **Per-source health.** `/health` gains an additive `sources` key that lists each active source by
  name and circuit state; the existing keys and the status code are unchanged.
- **Release packages.** A release publishes one sdist and one wheel for the core and for each released
  module, with `checksums.txt`. Every module carries the core version and pins
  `law-scrapper-mcp==<version>`, so a wheel refuses a core of another version. A new required CI job,
  `packages`, builds and installs them in a clean environment on every pull request.

### Changed

- **Egress per upstream host.** Every host has its own rate limiter, circuit breaker, concurrency lanes
  and cache namespace; a module starts from the Sejm's own rate and may only lower it, and its
  `User-Agent` adds a `module/version` token. A module client is pinned to its origin; a redirect to
  another host is refused with its own error category, which tells the agent to report it rather than
  retry. A source that fails is named in the error, which says the other sources are unaffected. Sejm
  behaviour, including its redirect handling, and every Sejm error text are unchanged.
- A source other than the Sejm that answers 401, 403 or 451 is reported as unavailable because it
  refused this server, without retry advice (new error category `source_refused`).
- When the cache is full, the namespace with the most entries is evicted first, so a busy source cannot
  push out the Sejm's entries. With one namespace it evicts exactly as before.
- While a source module is registered, `DU` and `MP` typed in another letter case or with surrounding
  spaces are sent to the Sejm as `DU` and `MP`. With no module every value is sent as typed, as in 4.4.2.
- The container image installs every released module, switched off (`LAW_MCP_SOURCE_MODULES=-*`), and
  the core sdist is built from an explicit file list instead of the working tree.
- `scripts/check_release.py --sync-version` also rewrites the version, the core pin and the `uv.lock`
  entry of every released module; `--build-packages` and `--check-installed` build and inspect the
  release set. `uv` is pinned to 0.12.22 in every workflow, and `pip-audit` covers module dependencies.
